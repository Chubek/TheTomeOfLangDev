Polyhedral Model Based Application Source Codes Analysis for ASIP Design
Xiaoyang Li∗ ,Wenbiao Zhou∗ , Dake Liu∗
∗ Institute of ASIP, School of Information and Electronics
Beijing Institute of Technology, Beijing, P.R.China 100081

Abstract—Application Specific Instructions-set Processors
(ASIPs) are needed to handle the future demand of flexible and
high performance computation in parallel real-time computing
domain. Current ASIP design methodologies are mostly based
on the accurate understanding of application source codes.
Profilers can automatically analyse source codes and get
interesting information from them to aid processor architecture
design. Dynamic profilers add extra instructions to source codes
and execute to generate basic block execution counts. This is
often infeasible in the domain of parallel real-time computing,
because of excessive execution time and the difficulty to define
typical stimuli in the early architecture design phase. Static
methods analyse source codes without executing them and are
faster and more accurate than dynamic ones. The static analysis
method proposed in this paper is based on polyhedral model.
It identifies code segments that execute frequently, or named
hot codes. It is usually a small part of the whole code base.
This information is provided to the architecture designer as
design guide. The hot codes may be implemented using custom
function unit to optimize the efficiency of the whole system. A
running example is used to illustrate the static method, and
the results are compared to dynamic profilers. Same results
are achieved by the two analysis methods.
Keywords-ASIP; program analysis; polyhedral model; architecture design

I. I NTRODUCTION
Application Specific Instruction-set Processors (ASIPs)
are a realistic solution to satisfy the current demand of
flexibility and high performance. Custom function units or
acceleration instruction sets are utilized to achieve high performance without sacrificing programmability. Architecture
designers should make decisions on which function parts be
implemented in hardware. Thus the design space of ASIP
architecture is very huge.
Source code analysis step is utilized in several design
flows before architecture design to narrow down the huge
design space of architecture choices [1]. ASIP design relies
on the accurate understanding of application source codes.
A common way to understand codes is profiling, which
is a technique traditionally used in software engineering
domain to optimize codes themselves for a particular processor architecture. µprofiler [2], [3] is a dynamic profiler
targeting ASIP architecture design. However, for real-time
parallel programming, such as multimedia and base-band
communication, typical input stimuli are hard to define
and design, and dynamic profilers suffer from long runtime. Static analysis methods are more appropriate in this

programming domain, as they are faster and accurate.
Polyhedral model is a complete representation of static
control parts (SCoPs) of programs [4]–[7]. It translates the
intermediate representations of compilers to a declarative
representation. Then translations and optimizations are done
in the polyhedral domain. Finally, intermediate representations are translated back from the polyhedral domain.
Comparing with traditional loop manipulation techniques,
such as peeling, splitting, fusion, reversal and interchange,
polyhedral model offers rich algebra representations and full
support for various kinds of loop transforms. It is a power
tool to analyse loop structures in application source codes.
The weakness of polyhedral model lies in its applicability
and the code generation stage. Polyhedral model accepts
only SCoPs, but any correct program, not just loop nests
with static control flows, should be accepted and analysed.
However, in the domain of real-time parallel programming,
computation intense parts are almost with static control
flows. Moreover, code analysers do not need the stage of
code generation. Thus, polyhedral model is suitable for our
purpose.
A static analysis method is proposed in this paper to find
out the hot segments in application source codes. To achieve
the same accuracy of dynamic profilers, execution counts of
basic blocks should be able to be determined. The static
analysis method is based on polyhedral model to analyse
loop iterations. Basic block costs are estimated and finally
hot code segments are identified. The contributions of the
paper include:
1) A static application source codes analysis method is
proposed for application domain of real-time parallel
programming.
2) Polyhedral model is used to translate codes for loop
iteration estimation, and hot codes could be identified by comparing weighted areas in 2-D polyhedral
model, or volumes in 3-D polyhedral model.
3) A basic block cost estimation method is proposed for
the re-targeting nature of ASIP profiling.
The paper is organized as follows. Section 2 introduces the
design of static application code analysis method. Section 3
shows the analysis results using an example and compares
the results with dynamic profiler. Section 4 concludes.

II. S TATIC APPLICATION CODE ANALYSIS
This section introduces the design of static analysis
method. After identifying SCoPs by polyhedral optimization,
it firstly establishes polyhedral models and determines loop
iterations of every loop. Secondly, costs of basic blocks
inside loops are estimated. Finally, hot codes are identified
based on 90/10 rule.
A. SCoP identification
Application source codes are analysed to identify SCoPs,
which can be accepted by polyhedral model. The SCoPs
have some rules to follow. Firstly, it contains only structured
control flows. for style loops are only allowed. Secondly,
loop bounds, conditions and access functions have only
affine expressions of loop induction variables of the current
loop or the outside loops. Finally, the codes are side effect
free. With the optimization passes inside the compiler, the
above requirements could be simplified to adapt wider cases.
With -O3 optimization option, especially with the help of
loop simplification, anything that acts like a regular for a
loop can be simplified to induction variable, and the loop is
translated to for style loops inside compiler. By the help of
expression simplification, expressions that calculate an affine
result, instead of affine expressions, are accepted. Side effect
known can replace the side effect free.
After identification of SCoPs, the code segments that meet
the requirement of static analysis are translated to polyhedral
models for loop iterations determination.
B. Loop iterations
The polyhedral model represents loops by iteration domains. These domains need some transforms to break large
domains to smaller ones. The small domains do not contain
if branches and the iterations counts could be determined.
Loop canonization simplifies the loop structures to only
one induction variable, and simplifies the induction variable
stride to one. The iteration domain of depth-three loops is

function acts like a line and divide the polyhedral area to

Memory allocation and access operators, such as alloca,
load and store, are not considered. Operators that contribute to the processor architecture decision are fadd,
fmul and fdiv, which are add, multiply and division
operators. sin function also contributes to the cost. For the
target processor architecture, assume the costs of operators
are represented by the consumed processor cycles. The cost
of add and multiply is 1, and 20 for division. sin function
is implemented using Taylor expansion, and the cost is 30.
Therefore, the total cost is 53 for this basic block.

IV. C ONCLUSIONS AND FUTURE WORK
A static analysis method is proposed to identify hot
segments in application source codes. The method is based
on polyhedral model to determine the iterations of loops.
The results exactly match the results of dynamic profiler. The
static profiler does not execute the source codes to analyse
them, and thus is faster than dynamic profiler.
