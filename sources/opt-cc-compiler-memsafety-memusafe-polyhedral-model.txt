The polyhedral model provides a single unified foundation for systolic array synthesis and automatic parallelization of loop programs. We investigate the problem of memory reuse when
compiling Alpha (a functional language based on this model). Direct compilation would require
unacceptably large memory (for example O(n3 ) for matrix multiplication). Researchers have previously addressed the problem of memory reuse, and the analysis that this entails for projective
memory allocations. This paper addresses, for a given schedule, the choice of the projections so
as to minimize the volume of the residual memory. We prove tight bounds on the number of
linearly independent projection vectors. Our method is constructive, yielding an optimal memory
allocation. We extend the method to modular functions, and deal with the subsequent problems
of code generation. Our ideas are illustrated on a number of examples generated by the current
version of the Alpha compiler.

1. INTRODUCTION
The polyhedral model is a formalism for reasoning about massively parallel computations (potentially even infinite) with a compact (finite) representation. It was
originally developed in the context of systolic array synthesis, and uses a generalization and extension of the systems of Uniform Recurrence Equations first proposed
by Karp et al. [1967]. This generalized formalism is called Systems of Affine Recurrence Equations (SAREs) over polyhedral domains (the domain of a recurrence
equation is the set of index points where it is defined).
Feautrier paved the way for its use in parallelizing compilers by showing that by
performing exact data flow analysis [Feautrier 1991] on a certain class of loops in
an imperative program (called static control loops), one obtains an intermediate
(dynamic single assignment) form which is isomorphic to an SARE over polyhedral domains. The PAF (paralléliseur automatique de Fortran) project underway
in his group uses a generalization of systolic scheduling and allocation techniques

In this paper we address the problem of generating memory-efficient code from
systems of affine recurrence equations over polyhedral domains, once a parallel
schedule is determined. Our work is presented in the context of a parallelizer/compiler for Alpha (we will use the expressions “SAREs over polyhedral domains” and
“Alpha programs” interchangeably), but the methods presented here can be easily
adapted to other contexts. Indeed, regardless of whether one starts from singleassignment code (as in a functional language like Alpha) or whether one produces
it as an intermediate form (in order to expose all the potential parallelism, by
getting rid of output and antidependences), it is inefficient to produce the final
code in this form, so our techniques are applicable in either case.
To understand the problem, let us consider compiling (or otherwise executing)
computations specified as SAREs over polyhedral domains. Wilde and Rajopadhye [1995] originally presented the following strategy for compiling an Alpha program:1 (i) allocate enough memory for the bounding box of the domain of each
variable; (ii) visit the index points in the domains of the output variable(s) in any
order (say lexicographic); and (iii) at each point, use demand-driven evaluation, suspending and recursively evaluating any unevaluated arguments if necessary. This
strategy is identical to an interpreter, with a memoizing optimization [Keller and
Sleep 1986] that avoids recomputation (in the case when the domains are infinite,
variants of this can be used). Quinton et al. [1995b] showed how the overhead of
suspensions can be avoided, leading to an imperative loop program with a two- to
five-fold improvement in running time (in the sequential case). The same method
can also be used to generate parallel code [Quinton et al. 1995a].

Alpha included) being inherently single-assignment, the generated code is memory1 Although naive, this is an essential fall back strategy, in case the analysis (described later) to

The main idea is that we allocate computations to memory cells by projections
of domains. Specifically, for each equation, X defined over a domain DX in the
SARE, the result of computing X(z) for some point z ∈ DX is allocated to memory
location ΠX z, where ΠX is a projection. For such a memory allocation scheme to
be valid, we must ensure that no live value is overwritten, i.e., any (re)write into
a memory location must occur after the last utilization of its previous contents.
Wilde and Rajopadhye provided conditions under which such an allocation was
valid.
In this paper, we first generalize this to pseudoprojections which permit modulo
addressing, and then, for a given schedule for the program, we deal with the choice
of the projection so as to minimize the memory used. Our assumption of fixed
schedule is a standard one made in all related work to date on this subject. Simultaneously choosing the schedule and the memory allocation functions optimally is
an interesting open problem, but is beyond the scope of this paper.
Our main result is that we give tight bounds on the number of linearly independent (pseudo) projection vectors. Our lower bound proof is constructive, thus
yielding an optimal memory allocation. We show how pseudoprojections can be
naturally combined with a “windowing” optimization proposed by Lefebvre and
Feautrier [1997]. Our adaptation improves their method and simplifies the subsequent steps of code generation. Our ideas are illustrated on a number of examples
generated by the current version of the Alpha compiler.
The remainder of this paper is organized as follows. Section 2 describes the

mathematical foundations for our analysis including definitions of the next-write
function, the usage set, and the lifetime function. Next, Section 4 formulates the
constraints that memory allocation function must satisfy. In Section 5 we extend the

Section 10 describes related work, and Section 11 presents our conclusions.

2.1 Semantics of Alpha Expressions
As described above, an Alpha expression is either (i) a variable or constant, (ii)
a pointwise operator applied to one or more (typically two) expressions, (iii) the
restriction of an expression to a domain, (iv) a case expression, (v) the composition
of an expression with a dependency, or (vi) a reduction. We will now briefly and
intuitively summarize the semantics of Alpha expressions.
Alpha is a data-parallel language, and hence expressions denote collections of
values. Indeed all expressions (not just variables) can be viewed as multidimensional arrays and denote a function from indices to values. Alpha semantics
[Mauras 1989] consist of two parts: a semantic function and a domain. The semantic function is defined using classic methods and is fairly obvious (the only
subtle point being dependencies), but the domains are a unique aspect of Alpha.
Every (sub) expression in a program has a domain, and it can be determined from
the domains of its subexpressions, as summarized below.
—Identifiers and Constants: An identifier simply denotes the variable it identifies,
and is defined over its declared domain. In general this is a finite union of
polyhedra. A constant expression denotes the constant itself, and its domain is
Z 0 , the zero-dimensional polyhedron.
—Pointwise Operators: The expression E ⊕ F denotes the pointwise application of
the operator ⊕ to the corresponding elements of the expressions E and F, and
hence its domain is Dom(E) ∩ Dom(F), the intersection of the domains of its
subexpressions. There may be unary or ternary (the if-then-else which is strict )
pointwise operators, with similar semantics.
—Restriction: The expression D : E denotes the expression E, but restricted to the
domain D, and hence its domain is D ∩ Dom(E).
—Case: The expression case E; F esac denotes an expression which has alternative
definitions (there may be more than two alternatives). Its domain is Dom(E) ∪
Dom(F), the (disjoint) union of the domains of its subexpressions.
—Dependency: First, note that the dependency (z → f (z)), by itself, simply denotes the affine function, f. Now, the expression E.(z → f (z)) denotes an expression whose value at z is the value of E at f (z). Its domain must therefore be
the set of points which are mapped by f to some point in the domain of E. This
is nothing but the preimage of Dom(E) by f .

The dependency can be viewed abstractly as a mechanism for aligning dataparallel objects. For example consider the expression A+B.(i,j->j,i). The
standard view of this is an expression whose value at the point [i,j] is the
sum of A[i,j] and B[j,i]. Alternatively we may also view the subexpression
B.(i,j->j,i) as the transpose of B which is aligned with A by the + operator.
—Reductions: The expression reduce(⊕, (z → f (z)), E) denotes an expression
whose domain is the image of the domain of E by f . Its value at any point,
z, in this domain is obtained by taking all points in the domain of E which are
mapped to z by f , and applying the associative and commutative operator ⊕ to
the values of E at these points.
Due to the mathematical closure properties of polyhedra and affine functions
[Mauras 1989], the domain of any Alpha expression is a finite union of integral
polyhedra, and is determined automatically by a library for manipulating polyhedra
[Wilde 1993].
These closure properties have an important consequence. Every expression can
be simplified into a unique normal form, called the case-restriction-dependency
form. It consists of an (optional) outer case, each of whose branches is a (possibly
restricted) simple expression. A simple expression consists of either variables or
constants composed with a single dependency function (if this is the identity, it
may be omitted), or pointwise operators applied to such subexpressions. This
simplification is obtained by a set of rewrite rules which combine dependencies
together, eliminate empty domain expressions, etc.

an Alpha program (observe that the domain of the constant 0 is Z 0 , whose preimage by the function (i, j →) is Z 2 which is coherent with the rest of the expression).
Since the right-hand side of this equation is a normalized expression, we can always
(i) rename the indices in the restrictions and in the dependencies to be identical
(say, by by replacing p and q by i and j, respectively), and then (ii) move the
index names in the dependencies (left of the “->”) and in domains (left of the “|”)
to the left of the entire equation, yielding the following “sugared” syntax, which is
often more readable.
X[i,j] = {| 0<i,j<=N} : X[i,j] + 0[]
This is called the array notation, and indeed, all subsequent examples in this paper
are normalized and presented in this notation.

Perhaps the most important transformation in the Alpha system is the change
of basis (COB). The intuition behind it is as follows. Since an Alpha variable
can be viewed as a multidimensional array defined over a polyhedral domain, we
should be able to “move” (or otherwise change the “shape” of) its domain and
construct an equivalent program. In MMAlpha, a COB can be applied to any
local variable, say X, using any affine function, T that admits a left inverse T −l
for all points in the domain of X. The following changes are made to the program,
yielding an equivalent program
—Replace DX , the domain of X by T (DX ), its image by T .
—If E is the expression on the right-hand side of the equation defining X, replace
it by E.T −1 .
—Replace all occurrences of X on the right-hand side of any equation by X.T .
Many program transformations such as alignment, scheduling, processor allocation, etc., can be viewed as special cases of COB.

Scheduling. Alpha is based systems of affine recurrence equations (SAREs), and
the SARE scheduling problem has been well studied [Rajopadhye and Fujimoto
1990; Feautrier 1992]. It may be formulated as follows. For each variable X in a
SARE, determine a function tX (z) which gives a k-dimensional vector representing
the time instant at which X(z) is computed. The time function must respect causality: whenever X(v) depends on Y(v 0 ), then tX (v) ≺ tY (v 0 ). In general, the form of
the schedule is a multidimensional affine function, viewed geometrically as families
of hyperplanes. The schedule provides the first k rows of the COB transformation,
and allows one to then interpret the k first dimensions of a variable domain as the
time instant of its computation.

In the context of the polyhedral model and affine schedules, a most natural choice
for the class of memory allocation functions is linear projections. These functions
define both memory allocations and addressing functions for the variables of a
system. A static analysis of the Alpha program yields information which can used
to automatically compute valid projections. The analysis is done at compile time
and does not involve runtime operations (such as dynamic memory allocations),
thus avoiding any execution overhead. In this section we first introduce some basic
machinery and then formulate the constraints that a memory allocation function
must satisfy. We will use the forward substitution program (Figure 2) as a running
example.
We are given an Alpha program with a k-dimensional schedule. Thus, for each
nY -dimensional variable, Y, with domain DY ⊆ ZZnY , we have an affine function
specified by a k × nY matrix ΛY , and a k-vector αY , denoting the fact that Y(z) is
computed at time instant ΛY z +αY . We seek to determine a linear function, MemY ,
which, for each point z ∈ DY , specifies the memory address where Y(z) is stored.
This function is an mY -dimensional projection, i.e., MemY (z) = ΠY z, where ΠY
is an (nY − mY ) × nY integral matrix. Thus, the resulting image of DY under the
allocation function is (contained in) an (nY − mY ) dimensional polyhedron, i.e.,
mY dimensions are “projected out.”

6. OPTIMAL MEMORY PROJECTION
Having established the constraints on the projections and pseudoprojections, we
now address the choice of the ρi vectors. Note that there are many sources of
memory savings. The volume of a polyhedron (or its bounding box) is a polynomial
of its size parameters. Its degree is the dimension of the polyhedron under the
assumption that the domain is large enough as previously described (if the domain
has equalities, Az = a, where A is l × nY , the effective dimension is reduced by
l). Hence, we contend that the primary criterion for optimality is the number
of linearly independent projection vectors. Each such vector contributes to the
reduction by 1 of the degree of the polynomial giving the total memory usage. Even
for pseudoprojections, the total memory volume is still a polynomial whose degree
is nY − mY , of course with a constant multiplicative factor of det(S). Therefore we
seek first and foremost to maximize the number of linearly independent (pseudo)
projection vectors.
Other sources of optimization include combining the domains of variables, and
transformations that seek to increase the ratio of the volume of a polyhedron to
the volume of its bounding box [Rajopadhye and Wilde 1993]. They give, at best,
a constant factor improvement.5 Furthermore, special care is needed when the
domain does not grow in all dimensions with the size parameters, or when one of
them is much larger than the others (e.g., an n × m domain where n  m, or a
banded n × n matrix of width w). An extreme case is when the constraints that
specify the domain include equalities (the so-called lineality space of the domain).
Such secondary criteria are addressed in Section 7.
Recall that an obvious upper bound on the number of linearly independent allocation vectors is k. Also note that this bound is weak and cannot always be
achieved (indeed, were this so, every sequential program could be executed with
only a fixed size memory). We now develop tight bounds. We first recall a standard definition from the parallelizing compilers literature [Banerjee 1993; Allen and
Kennedy 1984].

7. EXTENSIONS
We have formulated the constraints that a memory allocation function must satisfy,
and proposed a solution that satisfies these constraints optimally. The complexity
of our solution is polynomial in the number of dimensions (essentially we determine
the null spaces and right inverses of affine functions). Our solution is optimal in the
sense that the number of projection vectors is maximized. As we have argued in the
introduction, this is the primary optimization criterion. In practice, a number of
secondary criteria are also important depending on the “shape” of the domain. For
example, consider a banded matrix computation where the domain of the variable
is the strip defined by the points [1,1], [10,1], [N,N-9], and [N,N]. If the lifetime

Another optimization is to consider what is called the lineality space of variable domains. In Alpha, it is likely that successive transformations, including
scheduling and the previously described change of basis, add dimensions to variable
domains. Typically, this is because unimodular completion of the transformation
is required. For example, a vector (a variable with a one-dimensional domain)
may need to be embedded in a two-dimensional space (say, if the schedule is twodimensional due to the dependencies on among other variables of the program)—we
already have seen this for the variable x in the forward substitution example. Hence,
the domains of variables may have a lineality space (i.e., the constraints that define
them contain a number of equalities). Allocating memory for a bounding box of
such domains is obviously a huge waste of memory. A simple optimization would
simply ignore the dimensions corresponding to the lineality space and change access
functions consequently in the program. This is incorporated in our code generator.

9. APPLICATIONS OF THE METHOD IN PARALLELIZING COMPILERS
In this section, we illustrate how the techniques presented here can be used in parallelizing static control loops in a conventional imperative language. It is well known
that the key hindrance to parallelism detection and exploitation is the fact that in
addition to true dependencies (flow dependencies) one has to contend with anti- and
output dependencies, which are not really intrinsic to the computation but merely
a side-effect of the desire of the programmer to reuse memory. To overcome this, a
number of authors have proposed various techniques to remove spurious dependencies to a greater or larger extent: array privatization, static single-assignment, and
full (or dynamic) single-assignment [Maydan et al. 1993; Knobe and Dally 1995].
The exact dataflow analysis due to Feautrier [1991] is an extreme but complete
solution which proposes a dynamic single-assignment form. The following material is not original, and draws upon the work of Feautrier. It is given here for
completeness’ sake.
We wish to parallelize nested loop programs which satisfy the following restrictions (called static, or affine control loops):
—loop lower (cf. upper) bounds are either (i) affine expressions involving only
program parameters and/or surrounding loop indices, or (ii) the maximum (cf.
minimum) of finitely many such expressions;
—the only data type involved is the multidimensional array (scalars are considered
as zero-dimensional arrays);
—statements are restricted to assignments to array variables, and the arguments
used on the right-hand sides of the assignments are arbitrary expressions involving
such operands. The operators are considered strict (function calls are assumed
to be side-effect-free and atomic);
—arrays are accessed (whether on the right- or on the left-hand sides of statements)
with affine functions of the program parameters and/or surrounding loop indices;
and
—conditionals, if any, are restricted to be affine (in) equality guards involving the
program parameters and/or surrounding loop indices.
Reaching definition analysis is a standard compiler analysis, which seeks to determine for any variable read during any statement, which was the specific assignment
that produced the value being read [Aho et al. 1986] (i.e., the source of a read). In
its simplest form, it is restricted to scalar variables in straight-line code. What we
desire is a fine-grained reaching definition analysis for programs with loops (hence,
multiple instances of statements) and arrays which we do not desire to approximate
as a single monolithic variable (hence multiple elements). However, we would like
the result and the analysis to be be compact—it is unacceptable if the information
was derived and/or presented by enumerating all the instances of statement and/or
elements of arrays.

analysis can be performed for static control loops, and how the results can be

static control loops:
—Perform exact dataflow analysis in order to determine the pure (flow) dependencies of the original program. This will necessitate going to a single-assignment
form, but this is temporary. This step will expose (but not necessarily exploit)
all the potential parallelism.
—Determine a schedule for the program. It is here that we choose how much
parallelism to really exploit.
—Given the schedule, determine the memory allocation functions. Our optimality
results guarantee that there will be no unnecessary (in the precise sense as modeled by our const function) wastage, i.e., the final program will have just as much
memory expansion as needed for the degree of parallelism that we have chosen
to exploit.
10. RELATED WORK AND COMPARISON
Chamski [1993] does lifetime analysis in an earlier version of the Alpha compiler
and briefly introduces the idea of windowing and modulo addressing (without specifying how to determine the relevant bounds). However, his model is somewhat
restrictive. First, the schedule is assumed to be full-dimensional. Next, his definition of the lifetime requires all dependencies to admit a left inverse. And finally,
the modular addressing and projections are restricted to only canonic directions.
In the context of compiling multimedia applications for embedded systems, De
Greef and Catthoor [1996; 1997] have proposed strategies to reduce memory requirements for static (affine) control loop programs with multidimensional arrays,
and use a two-phase strategy. The first phase deals with the memory allocation for
each array. Their model also uses (piecewise) affine execution order and memory
allocation functions, but they formulate an optimization problem which is not linear, and whose solution is expensive to compute. During the second phase, they
exploit the result of the first phase to globally optimize the memory allocation of
all the arrays.

compiler decides how much parallelism is to be exploited.
Lefebvre and Feautrier also use the polyhedral model, and have similar techniques
(indeed, the windowing analysis we presented here draws from and improves upon
a similar analysis developed by them). They perform the analysis before array
expansion, and pose the question of whether a dimension has to be introduced
to respect direct flow dependencies. Although their problem is not posed as a
projection, they also ultimately find the same minimal number of projection vectors
as our methods (but the optimality is not proved). Since the total memory size
obtained by both methods is asymptotically the same, we may compare our results
with theirs with two criteria—the constant factors in the residual memory, and the
complexity of the algorithms.
The Lefebvre-Feautrier method does array expansion “judiciously” (only when
it is necessary, as indicated by the variable lifetime). However, the expansion
dimension corresponds to the indices of the original loop indices. In other words
in the vocabulary introduced in this paper, they allow only canonical memory
projections, and the lifetime vector is approximated by a multiple of some canonic
vector, ei . This could lead to over-allocation of memory by a factor as high as
2. For example, consider an N × N iteration space where the computation has a
lifetime of (1, 1)T . Their method would allocate an N × 2 window. Our method
would first apply a change of basis by the function (i,j -> i,j-i), rendering the
T
lifetime vector (1, 0) . The windowing calculation would then yield a bound of
N + 1, and would allocate exactly N + 1 memory locations. In this example, the
change of basis introduces the need for a cyclic addressing; there is no need for it
when using a canonical projection. In the general case, however, we do not make
any assumption on shapes of domains, and the change of basis does not yield any
run-time overhead. Also note that one can also construct examples (usually with
somewhat extreme aspect ratios) where their method is better by a constant factor.
In terms of computation time, our first method without windowing is very fast
(polynomial). Moreover, any method based on windowing is relatively expensive,
since each computation of δi requires the resolution of an integer linear programming problem. Our method performs this computation for only the actual memory
dimensions (i.e., nY − mY times), whereas the Lefebvre-Feautrier method would do
it nY times, since the memory analysis is performed on the original program.
Our work also has some relations to functional programming, especially the manipulation of arrays and memory. We first briefly recall this work and then compare
with our approach.

(for initial expressions) or in parallel (for expressions), and this is specified by
the programmer. In the notation of this paper, the user must explicitly schedule

The computation readily admits a wavefront parallelism (all points on the line

and it may be time to reconsider the language decision.
The SISAL compiler performs a memory reuse optimization which is based on
the well-studied “in-place-update analysis” problem [Hudak and Bloss 1985], and
seeks to resolve the following question: given a sequential loop, is it legal to reuse
the memory of the previous iteration for the arrays updated in the current iteration,
rather than copying the old values. In the notation of this paper, this reduces to
determining whether a memory allocation function specified by a projection along
the innermost time index is valid.
I-structures [Arvind et al. 1989] are data structures which allow direct specification of recursive computations like (16). Array comprehensions provide a concise
notation for describing sets of indices (somewhat like the domains in Alpha, except that they are one-dimensional, and may not necessarily be convex and/or contiguous). These two features are now standard in the functional language Haskell.
I-structures also allow reduction operations, and the storage for intermediate values
of such computations is easily optimized using standard tail-recursion optimization
methods. However, I-structures sacrifice referential transparency and determinism:
it is up to a run-time system to detect if the single-assignment property is violated,
and if so, cause an exception. Furthermore, the parallelism is specified as fine-grain,
run-time parallelism, and could result in overheads of context switching, etc. Once
again, the compiler uses update analysis in order to safely reuse memory, whenever
possible. However, note that such analysis (whether for I-structures or for SISAL)
will not enable to compiler to reduce memory, as we have observed for a number of
examples using out methods.
It must be pointed out that SISAL and I-structures are more general than Alpha, which is restricted to static (affine) control programs.6 and hence the run-time
strategies adapted by them are valid and necessary implementation choices. Nevertheless, the methods presented here could be used to propose a class of efficient,
static control, polyhedral arrays in such languages, where the compiler can have
much control.

11. CONCLUSION
We have addressed the problem of memory size optimization when compiling Systems of Affine Recurrence Equations (SAREs) defined over polyhedral index domains. This formalism, called the polyhedral model, is useful for loop parallelization
and systolic synthesis. Our work is in the context of compiling Alpha, a functional
data-parallel language based on this formalism. We start with a refinement and
extension of the model of Rajopadhye and Wilde [1996], by clarifying some assumptions, and extending the reuse analysis to modular projections. Our main
contributions can be summarized as follows:
—Determining a tight bound on the number of linearly independent memory projections, thus achieving optimal memory reduction.
—Extending the techniques to modular mappings. This extension is crucial in order
to treat even simple cases such as the Fibonacci (i.e., programs with uniform but
nonprimitive dependencies). Without such allocation functions, the Fibonacci
program would not have allowed any memory reduction, although the lifetime of
the variable is just 2, and two registers suffice in practice!
—It turns out that it is sufficient to have such modular allocations in only one
dimension to fully exploit memory reduction due to such uniform dependencies.
However, if we analyze the window of the lifetime in each dimension separately,
we are often able to obtain considerable additional reduction. For example, in
the case of “skewed” infinite (or even banded) domains, one may seemingly need
infinite (or very large) memory resources, but with the windowing analysis we
obtain considerable savings, almost as if we had and additional projection vector.
Finally, we mention an important open problem. In our analysis, we assume
that the schedule is given. Although there are techniques that automatically yield
(optimal) schedules, the optimization involved seeks the fastest schedule. For the
goal of minimal memory implementation, the fastest schedule may not be globally
optimal. This is an interesting open problem. Additional constraints such as a
maximum degree of parallelism could also be imposed.
